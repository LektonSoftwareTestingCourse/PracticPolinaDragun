## Чек-лист дымового тестирования

**Инфраструктура**
- [ ] `docker compose up` поднимает все контейнеры, все они в состоянии healthy.
- [ ] PostgreSQL принимает подключения, необходимые таблицы созданы.
- [ ] RabbitMQ запущен, exchange `smp.transactions` и очередь `transaction-log` существуют.

**Сервисы**
- [ ] Gateway `/health` отвечает `ok` и показывает `ok` для Switch, Authorization, Card Management, Logger.
- [ ] Switch `/health` показывает доступность Authorization.
- [ ] Authorization `/health` показывает доступность Card Management.
- [ ] Card Management `/health` отвечает и показывает число карт в базе.
- [ ] Transaction Logger `/health` отвечает и показывает число сохранённых транзакций.
- [ ] Bin Lookup, Terminal Simulator и Merchant Acquirer Simulator отвечают на `/health`.

**Сквозная проверка**
- [ ] `POST /api/cards/generate` создаёт тестовые карты.
- [ ] Покупка через `POST /api/transactions` получает ответ со статусом и `responseCode`.
- [ ] Эта покупка находится в Transaction Logger.
- [ ] Web Dashboard открывается, индикатор WebSocket-соединения зелёный

## Чек-лист критического пути

**Деньги клиента**
- [ ] Одобренная покупка резервирует на карте ровно сумму транзакции.
- [ ] Отклонённая покупка не меняет баланс карты.
- [ ] Покупка на весь остаток баланса одобряется, на сумму больше остатка  отклоняется с кодом 51.
- [ ] Покупки за день суммируются: покупка, с которой сумма за день превышает дневной лимит, отклоняется с кодом 61.

**Допуск карты к оплате**
- [ ] Покупка по заблокированной или неактивной карте отклоняется.
- [ ] Покупка по карте с истёкшим сроком действия отклоняется с кодом 54.
- [ ] Покупка по несуществующей карте или с неизвестным BIN отклоняется с кодом 14.
- [ ] Покупка направляется банку-эмитенту, соответствующему BIN карты.

**Достоверность учёта**
- [ ] Каждая покупка  одобренная и отклонённая сохраняется в журнале со статусом и причиной отказа.
- [ ] Если журнал не подтвердил запись, одобренная покупка откатывается и резерв возвращается на карту.
- [ ] Повторная доставка транзакции в журнал не создаёт дубликат.

**Мониторинг для оператора**
- [ ] Новая покупка появляется на дашборде в реальном времени.
- [ ] Число транзакций, approval rate и общая сумма на дашборде совпадают с данными журнала.
- [ ] Суммы на дашборде показаны в рублях, номер карты замаскирован.
